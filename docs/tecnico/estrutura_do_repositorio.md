# 🌅 Estrutura do Repositório — Projeto Aurora

## Objetivo

Definir a organização inicial do repositório do Aurora no GitHub.

A estrutura deve facilitar manutenção, evolução do projeto e entendimento por outros desenvolvedores.

---

# Estrutura inicial


│ ├── docs/ │   ├── historia_do_projeto.md │   ├── visao_do_projeto.md │   ├── requisitos_mvp.md │   ├── regras_de_negocio.md │   └── arquitetura_sistema.md │ ├── frontend/ │ ├── backend/ │ ├── database/ │ ├── assets/ │ ├── README.md │ └── .gitignore


---

# Pastas principais

## docs/

Responsável pela documentação do projeto.

Inclui:

- Ideias iniciais.
- Regras.
- Planejamento.
- Decisões técnicas.
- Design.

---

## frontend/

Responsável pela interface do usuário.

Possíveis tecnologias:

- HTML.
- CSS.
- JavaScript.
- React (futuro).

Contém:

- Telas.
- Componentes.
- Estilos.

---

## backend/

Responsável pela lógica do sistema.

Contém:

- APIs.
- Autenticação.
- Regras de negócio.
- Comunicação com banco de dados.

---

## database/

Responsável pela organização dos dados.

Contém:

- Modelos.
- Estrutura das tabelas.
- Configurações relacionadas ao banco.

---

## assets/

Responsável por arquivos visuais.

Exemplos:

- Logo.
- Imagens.
- Ícones.
- Protótipos.

---

# Arquivo README.md

Será a apresentação principal do projeto no GitHub.

Deve conter:

- Nome do projeto.
- Descrição.
- Objetivo.
- Tecnologias.
- Funcionalidades.
- Como executar.

---

# Arquivo .gitignore

Responsável por impedir que arquivos desnecessários sejam enviados ao GitHub.

Exemplos:

- Senhas.
- Configurações privadas.
- Dependências locais.

---

# Princípios de organização

O Aurora deve seguir:

✅ Código separado da documentação.

✅ Pastas com responsabilidades claras.

✅ Histórico de alterações organizado.

✅ Facilidade para evolução futura.
